**Status:** Controlled legal-review template — blocked  
**Accountable reviewer:** Lead practising Egyptian lawyer  
**Classification:** Fully fictional, synthetic-only  
**Boundary:** **No approval recorded.** This packet does not create an engagement, matter, authority, or clearance. No automatic conflict clearance, name merge, client creation, or matter access is permitted.

## Reviewer instructions

For each scenario, the lawyer records the controlling Arabic legal/professional source location, interpretation, disposition, escalation rule, and release consequence. Engineering supplies only fictional facts, provenance, UI/API/state evidence, and negative tests. A test pass is not a legal conclusion.

Every result must be approved, conditional, rejected, or deferred. A conditional result must name the exact scope, compensating behaviour, owner, expiry/review date, and release impact. Where facts are incomplete, the safe system action is record/rout/escalate; it is never auto-clear, auto-engage, or auto-open-matter.

## Common technical boundaries

- A missing, exact, or similar name cue cannot clear a conflict.
- An enquiry, candidate, consultation, payment, or representative assertion does not create a client, engagement, authority, matter, or access.
- Candidate facts may be shown only to an exact authorized reviewer; a generic denial discloses neither existence nor match rationale.
- Future M3 commands must be explicit: record enquiry/candidate, request information, submit for review, record authorized disposition, activate engagement, and open matter. A generic status change is prohibited.
