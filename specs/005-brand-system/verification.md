## Defect found and corrected during implementation

The contrast test found that the existing focus indicator — `3px solid var(--lg-gold-600)` on the warm-white ground — measures **2.82:1**, below the 3:1 that WCAG 2.2 SC 1.4.11 requires of a focus indicator. The pre-existing browser test asserted only `outline-style: solid`, which is why this was never caught.

LG-BRAND-001 assigns gold-600 to "Focus and controlled emphasis" and states that focus uses visible gold contrast, so the approved token was **not** reassigned. Instead the indicator now carries a navy-900 outer ring with the gold inside it: the gold stays visibly the focus colour, and the ring that meets the ground carries the contrast. This is the text/pattern reinforcement LG-BRAND-001 itself requires where colour carries meaning. `contrast.test.ts` retains the 2.82:1 measurement as a documented regression guard so gold cannot silently become the outer edge again.

## Manual accessibility assessment (FR-011)

Automated scanning is not accessibility evidence on its own. Performed 2026-08-10 against the production build, both locales.

- **Keyboard traversal, English**: Tab reaches the brand link as the first and only interactive element; the focus indicator is plainly visible against the warm-white ground after the correction above. No focus trap; no off-screen focus stop.
- **Keyboard traversal, Arabic**: identical behaviour with focus order following right-to-left reading order. Direction comes from the semantic `dir` attribute, not visual reversal.
- **Screen-reader output**: the shell exposes one landmark (`main`) labelled by the heading, one heading level 1, and a link whose accessible name is "Lex Gate". The Portal mark carries `alt=""` and is correctly ignored as decorative. The classification is announced from its text label, not from colour.
- **Reflow and resize**: no horizontal overflow or clipped content at 200% text size or at a 320 px viewport in either language.
- **Findings**: the focus-contrast defect recorded above was found by the contrast measurement and confirmed visually. No further issue found.
- **Limits of this assessment**: performed by the implementer against a foundation shell with a single interactive element. It is not a substitute for inclusive user review with Arabic-speaking assistive-technology users, which `CONSTITUTION.md` requires before any client-facing surface. That review is not yet due, because no client-facing surface exists.

## Residual risks and blocked items

- **Inclusive user review** with Arabic-speaking assistive-technology users has not occurred and is required before any client-facing surface. Not yet due.
- **Font subsets are narrow.** A name using a character outside the committed subsets falls through the declared same-script stack. The ordering makes that degrade legibly, but a future personal-name surface should re-check subset coverage against real Arabic name data.
- **No canonical requirement ID governs brand-token consistency or asset provenance.** This feature anchors to `I18N-RTL-001` and LG-BRAND-001. A dedicated requirement ID remains a sponsor decision.
- **The 31 MB brand source bundle is not committed** (decision D-007). Provenance is preserved by checksum rather than by byte comparison against an in-tree copy.
- **`packages/brand/src/tokens.css` is excluded from Prettier**, because the generator and the formatter would otherwise both claim authority over the same bytes. The parity test is that file's authority.

No exception is requested. No reviewer approval is required for this risk tier, and none is claimed.
